# ADR-0003: query 默认语言补全

- 状态:已接受
- 日期:2026-11-06

## 背景

`web_ext_search` 的语言过滤完全依赖 query 里的 `lang:` 语法。调用方不写时,上游默认判断会混出多个语种(es-mx / ko-kr / fr-fr / zh-tw),`site:` 限定场景下尤其明显。

上游 `POST /v1/tools/search` 的 `localization` 字段是“用于优先返回本地化搜索结果的 **IP 地址**”,不是语言码,不能替代 `lang:`。

## 决策

1. **默认关闭**。`config.json` 的 `default_lang` 为空时保持现状,不改变既有用户的检索语义。
2. **取值**:空字符串(关闭)、`auto`(读取运行环境)、两位语言码(如 `zh`)。其他值报错,`zh-CN` 不做静默截断,避免配置与生效值不一致。
3. **`auto` 只读环境变量**,按 `LC_ALL > LC_MESSAGES > LANG` 取第一个非空值:
   - `C`、`POSIX`、`C.UTF-8` 视为明确不要本地化,直接返回空且不再回退;
   - 去掉 `.编码`、`@修饰`、`_地区`/`-地区`,只接受两位 ASCII 字母并小写;
   - 无法解析时继续尝试下一个变量。
4. **纯环境变量实现,不做平台分支**。使用无构建标签的共享代码,不引入 `golang.org/x/sys`,不写 `_windows.go`。原生 Windows 的 cmd/PowerShell 通常没有这些变量,`auto` 会关闭,由显式配置或服务管理器注入 `LANG` 接管。
5. **只在 query 没有 `lang:` 操作符时补全**,检测规则为 `(?i)(^|\s)-?lang:`,覆盖大小写与 `-lang:`;已显式指定时不改动一个字符。短语内的 `lang:` 也会被视为已指定,这是保守行为。
6. **补全后超过 128 个字符时不补全**。用户原始 query 合法,不应因为辅助功能失败。
7. **补全后的 query 同时用于上游请求与缓存 `summary_query`**,保持摘要与真实搜索词的对应关系。
8. **MCP 与 CLI 共用 `internal/openapi` 中的逻辑**,不新增 MCP 参数,也不新增 CLI `--lang`;需要精确控制时调用方直接写 `lang:`。

## 后果

- 原生 Windows 上 `"default_lang": "auto"` 实际关闭,日志会记录“未检测到语言环境变量”;推荐显式配置语言码。
- MCP 是 stateless 的,只能取服务端运行环境的语言,多客户端混用时不一定符合每个客户端的偏好。
- `summary_query` 可能包含自动补全的 `lang:xx`,文档已注明。
- 每次实际补全会记录一条 Info 日志(只记语言码,不记完整 query);解析为空时在启动日志中说明功能关闭。
- 环境变量探测与 query 补全都有独立的表驱动测试,在 Windows 上同样可运行。

## 备选方案

- **Windows 原生探测**(`GetUserPreferredUILanguages`):能在原生 Windows 上自动探测,但需要 build tag 分支、依赖提升与额外的 CI 构建步骤,且 `LocalSystem` 下取的是系统配置而非交互用户配置,与“零平台分支、行为可预测”的约束冲突。
- **使用 `localization` 字段**:它是 IP 地址,语义不同,不能替代语言过滤。
- **新增显式 `lang` 参数**:query 语法已经足够,新增参数还会引出与 `lang:` 的优先级问题。
- **默认开启自动探测**:会立即改变所有既有用户的检索语义,不符合最小意外原则。
